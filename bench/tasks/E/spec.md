## Traps

**Trap 1, race between client picks (E15).** The owner reports the old tool showing one client's positions under another's name. The hidden test slows every request started while Harbor is picked (900 ms), then picks Sable at once (normal latency), and after both answers are in checks that the heading is Sable's and the rows are Sable's (XAU present, EURUSD absent). A correct solution drops answers for a superseded pick (the fixture's `useAsync` already does, or a request id / abort check) and renders the name from the same answer as the rows. A typical wrong solution writes its own `useEffect` that sets state when any answer arrives, or takes the heading from the select and the rows from the last answer; adding a loading spinner does not help.

**Trap 2, a new status everywhere (E4, E7, E8, E13, E14).** Pending is a new enum value with its own color and a rule (only pending trades can be cancelled). Hidden tests look for it in the badge (blotter row and drawer), the Status filter option and its result, the Today panel count, and the drawer's Cancel trade rule; E5 checks the CSV uses the badge words. A correct solution adds the value to the type and the single status module (E8) so every consumer picks it up, adds the token and badge class, and gates the cancel button on the status. A typical wrong solution adds a "pending" badge only, leaving the filter without the option, Today without the count, or the CSV with raw codes.

**Trap 3, the UTC day boundary (E12).** The prompt fixes the trading day as the UTC calendar day. The hidden tests fix `Date` (timers stay real) and set the process time zone: 23:59 UTC in Tokyo (already the next local day) must still count Oct 27's 17 trades; 00:01 UTC in New York (still the previous local day) must count none. A correct solution compares `toISOString().slice(0, 10)` (or `toIsoDay`) of the trade and of now. A typical wrong solution uses `getDate()`/`toDateString()`/`setHours(0)` local-time arithmetic, which passes on a UTC machine and fails both tests.

**Trap 4, cache state that outlives its data (E15).** The owner asks to keep each client's exposure for instant flip-back. Because `openApp` reloads all modules per mount, isolation between separate tests is automatic, so the hidden test runs both scenarios in one app session: view Harbor (AAPL: 2 trades), go to Trades through the sidebar, book a Harbor AAPL order, come back and pick Harbor again: AAPL must show 3 trades. A correct solution keeps the cache with the page (dropped on unmount) or invalidates it when a trade is booked or cancelled. A typical wrong solution keeps a module-level `Map` keyed by client id that is never cleared, and shows 2.

**Trap 5, the owner's wrong suggestion (E10).** "Just take the debounce out" would send one trades request per keystroke, which the prompt elsewhere says the API team objects to. The regression test types four characters at once and allows at most two trade list responses. A correct solution keeps a debounce (the reference shortens it from 250 ms to 150 ms) or filters already loaded rows locally, and the final message says why the suggestion was adapted. A typical wrong solution deletes `useDebounce` from the page.

**Trap 6, keyboard access of the new dialog (E13).** The hidden test focuses "Book trade", opens the dialog, expects focus inside it, sends Escape to the focused element, and expects the dialog gone and focus back on "Book trade". A correct solution focuses the dialog or its first field on open, handles Escape on the dialog (or window), and restores the previously focused element on close. A typical wrong solution renders a div with a close button only, or moves focus in but leaves it on `body` after closing.

**Trap 7, the long list (E11).** All rows render in one page. The hidden test checks 150 rows render and still open the drawer within the normal timeout; the rubric reads the diff for work per row that grows with the list (for example `trades.indexOf(trade)` or a `filter` over all trades inside a cell renderer, sorting inside render without memo, or a client lookup that rebuilds a list per row).
