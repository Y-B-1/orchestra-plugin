# Hook policy and boundaries

One classifier and two native adapters replace duplicated provider guards. Commands use a supported Python runtime and quoted plugin paths. Hook files are separate to prevent default discovery from loading duplicate handlers.

| Event | Effect | Does not do |
| --- | --- | --- |
| SessionStart | Supply main or worker contract and skill path; add the session id for `start --harness-session`; show a pending autonomy morning report | Seed state, repair files, resume, arm autonomy |
| SubagentStart | Supply worker boundaries to agents whose type starts with `orchestra:`; during an active run, tell any other agent to stop (advisory); otherwise return nothing | Veto native startup or authenticate identity |
| PreToolUse | Classify the call, apply the guard mode, and deny covered destructive Git, protected state/config patches; check recognizable releases and merges and, under autonomy or the unattended lock, the approval boundaries. Timeout 30 seconds, because the merged checks run Git | Interpret arbitrary scripts, aliases, stdin or all provider tools |
| Stop | Continue only when the coordinator can act now: a ready or reported card, an open final finding, a held chain owed its final review, or, with every card accepted, the final review, gates and pull request still owed. Running workers alone let the turn end (the harness wakes the session when one finishes), and a continuation is never repeated for an unchanged progress signature. Autonomy stops at the deadline, completion, a tampered ledger, a stall with no worker running, only parked cards, no live card or disarm; no pass or stall count stops it | Start an unrequested loop or continue corrupt state |
| UserPromptSubmit | When the whole prompt is the word `approved`, record the owner's receipt for a stopped run (see Approval and the merge guard). Timeout 10 seconds; any failure prints `{}` and exits 0, so it never blocks a prompt | Block or rewrite a prompt, or prove a human typed it |
| SessionEnd | Release the run bound to the ending session (see below) | Release on `clear` or `resume`; release a run started without `--harness-session` |

The PreToolUse matcher is `Bash|PowerShell|Edit|Write|MultiEdit|Agent|Task|CronCreate|ScheduleWakeup|RemoteTrigger|SendMessage` (`hooks/claude.json`, from `tools.claude_matcher` in `config/guard-rules.json`). An Agent or Task call carrying `agent_id` (made inside a subagent) is denied with "Workers do not delegate" in `protect` mode, during a run, or for an `orchestra:` agent, and a fresh mod marker never skips the Python hook for the Agent, Task, scheduler and `SendMessage` tools; the mod guards only Bash, Edit, Write and MultiEdit (`hooks.py` `_MOD_TOOLS`).

## Session end and the lease

`start --harness-session ID` binds the run to the Claude Code session. When that session ends with reason `logout`, `prompt_input_exit`, `other` or an unknown reason, the SessionEnd hook interrupts the run, so a lost lease never locks the next session out. On `clear` and `resume` the process continues under a new id and the run stays armed: the hook records a pending rebind, and the next SessionStart with source `clear`, `resume` or `fork` within 60 seconds binds the run to the new id. Runs started without a harness session are untouched. If the binding is lost anyway, read the actor and lease from `state.json` in the state directory and run `interrupt` with them; the lease is a consistency token, not a secret.

Claude's package has no Interrupt event. On user interruption, the main must stop workers through the harness and run the CLI `interrupt` before further dispatch. Late results cannot advance an interrupted engine run. An OS crash or hook timeout cannot prove that interruption was recorded: inspect actual processes and state before resuming.

## Command classes

The guard sorts every shell command into one class. Classification does not depend on run state; the hook then applies the run state.

| Class | Meaning | No run | Run active, `normal` | Run active, `protect` | Autonomy active, or stopped with its report kept |
| --- | --- | --- | --- | --- | --- |
| `allow` | No rule applies | allow | allow | allow | allow |
| `deny` | Always-deny rule, malformed command or protected path | deny | deny, except a softened deny (below) | deny | deny |
| `release` | One release-class command alone (non-force `git push`, `gh pr merge`, a `gh api` call that mentions merge, `gh release create`, `gh workflow run`, `gh pr edit --base`, a `gh api` write outside the pull request allow list, a `gh` command the classifier does not know, package publish including `cargo publish`, provider deploy) | allow | allow | allow with a current permit, else ask the user | deny, except the pull request push, the merge guard's allow and the pre-authorized release |
| `release-multi` | A release-class command inside a multi-command line | allow | allow | ask the user | deny |
| `boundary` | Deletion (`rm`, `git branch -d`, `git worktree remove` and similar), local merge, pull, rebase, cherry-pick | allow | allow | allow | deny, except cleanup and the rules in Autonomy boundaries; a local merge is allowed on a non-default branch |

The classifier always returns the strict (protect) verdict; `orchestra.py classify` prints it. A deny that carries `soften` is one that `normal` mode relaxes (`config/guard-rules.json` `soften`, `Decision.soften` in `guards.py`): `git stash` (every form), amend, a multi-ref push (`--all`, `--tags`, `--follow-tags`, `--delete`) and a push with a deleting `:branch` refspec warn; wholesale `add` and `commit -a` are allowed. `protect` mode, an active run under autonomy and the unattended lock keep these as denies.

Denied in every mode: force or mirror push, `--prune`, `+refspec`, `reset --hard`, `clean -f` without `-n`, wholesale checkout or restore and `switch -f`. A `--delete` push or `branch -D` is denied too unless it meets the merged-delete rules below. Raw ref deletion through `git update-ref` (`-d`, `--delete`, `--stdin`, or an all-zero new value) is denied with "Raw ref deletion is not allowed; use git branch -d". `git restore --staged` is allowed. A softened push that deletes a tag, the default branch or a protected branch, or whose default branch cannot be resolved, is denied in `normal` too (`hooks.py` `_soft_push_refusal`). A hook crash or a missing home directory denies the call (fail closed) and names the cause. While autonomy is active, edits to `autonomy.md` and `autonomy arm|disarm` from an agent are denied; the owner disarms, edits and arms again. A state file that exists but cannot be loaded (policy or repository changed, malformed) counts as an active run with no permit, and as autonomy-active when its raw flag says so or it is not valid JSON. The one exception is a state that parses with `session` null or `session.active` false: that ended run is inactive.

Shell parsing removes heredoc bodies and redirections first. A heredoc or here-string body is classified as a script when its consumer is a shell, `source`, `.`, `eval` or `xargs` running a shell, and is scanned for always-deny lines whatever the consumer. Command runners (`xargs`, `find -exec`, `doas`, `stdbuf`, `watch`, `flock`, `sudo`, `env` and similar) are unwrapped so the real command gets its class. Accepted costs: a data heredoc or producer that contains a bare destructive line denies, and a runner that ends in `-c` with no payload denies as malformed.

Accepted limits, because the guard is best effort and not hostile-worker isolation: encoded payloads (base64, `printf` escapes other than `\n`), variable or alias indirection, non-shell interpreters (`python3 -c`, `perl -e`, `node -e`), output process substitution, zsh `=(...)`, and `script` as a runner. Bash writes to protected paths, including the autonomy ledger and the mods marker directory, are not detected. Credential entry is not detected. MCP or terminal tools that push or merge are not guarded; using them to get around the guard is forbidden by procedure, not enforced. A `gh api` write outside a short allow list (create a pull request, comment on an issue or pull request, review a pull request, comment on a review) classifies as a release, category `apiwrite`; a `gh api` read is allowed. While autonomy is active the guard refuses to set or unset the Git configuration that routes or rewrites a push (aliases, `remote.*`, `url.*`, `push.*`, includes, `submodule.*`, `http.*`, `credential*`, `core.sshCommand`, `core.gitProxy`, `core.hooksPath`), through `-c`, `--config-env` or `git config`, and refuses `git config` forms it does not recognize and `git remote add`, `set-url`, `rename` and `remove`. It does not resolve an alias that already exists, so one defined earlier can still run a push or merge under another name. The run is found from the session directory, so a command run from a directory outside the repository and its worktrees (such as `git -C <run repo> push`) finds no run and gets neither the autonomy plane nor the unattended lock. That is a known gap; a server-side ruleset on the host is the only backstop that does not depend on the agent.

A linked worktree of a repository with a run gets the same state: the hook resolves the run from the main worktree. A separate clone is a different repository and has no run. Protected paths are the hook and config files of each harness, Orchestra agent files, any `.orchestra` component, the run state directory (except the coordinator's `progress.md`, `standing-orders.md` and `autonomy.md`) and the mods marker directory. `settings.json` is not protected.

## Agent guard and reviewer test block

- **Agent guard.** While a run is active (the hook loaded an engine whose session is active), an `Agent` or `Task` call from the main session whose `subagent_type` does not start with `orchestra:` is denied in `protect` mode, and in `normal` mode allowed with a warning, carrying "Orchestra run active: use an orchestra:* agent (investigator-code for search, builder for edits)". A missing, empty or non-string `subagent_type` counts as non-Orchestra. Outside a run nothing changes, and a call made inside a subagent still hits "Workers do not delegate". If the loaded engine errors while the hook checks the session, the call is denied only when the raw state file shows an active (or unreadable) session; an inactive raw session allows it.
- **Subagent guard.** While a run is active, any tool call made inside a subagent whose `agent_type` does not start with `orchestra:` is denied in `protect` mode (warned in `normal`) with "Orchestra run active: this agent is not an orchestra:* agent; stop and report. Start Agent and Workflow workers with an orchestra:<role> type". This covers agents a Workflow script starts, which never pass through `Agent` or `Task`; a Workflow agent with no `agentType` arrives as `workflow-subagent`. Such calls skip the mod fast path, so the Python guard always decides them. `SubagentStart` cannot block an agent, so during a run it gives a non-Orchestra agent the same text as context. The PreToolUse matcher covers shell, edit and agent tools only, so a read-only non-Orchestra agent can still read files; it is told to stop but not forced. `agent_type` is a routing hint, not authentication.
- **Reviewer test block.** A shell call from a subagent whose `agent_type` starts with `orchestra:code-reviewer` or `orchestra:critic` that runs a test suite is denied in `protect` mode (warned in `normal`) while `engine.current_gate_ids()` returns ids: "Cite gate receipt <ids>; reviewers do not rerun suites". Suite commands are `pytest`, `python -m pytest`, `python -m unittest`, `npm test` and `npm run test*` (also `pnpm`, `yarn`), `npx vitest`, `npx jest`, `npx playwright test`, `go test`, `cargo test` and `make test`, alone, after `cd x &&`, behind `env`, `time`, `uv run` or `bash -c`. A single-test probe is allowed: one unittest target naming a method (`tests.test_x.Class.test_y`) or one pytest `file::test` target. With no engine, an engine without `current_gate_ids`, an error from it or an empty list, the call is allowed. A fresh mod marker never lets these calls skip the Python hook, because only Python holds this rule. Like every shell rule it is best effort: an interpreter one-liner or encoded payload that runs a suite is outside it.

## Merged-branch deletion

`git branch -D <b>`, `git branch --delete --force <b>` (also `-d -f`, `-df` and abbreviated options) and `git push <remote> --delete <b>` or `-d <b>` (any prefix of `--delete`, flag before or after the remote) form the `merged-delete` category. It is a delete boundary, not a new boundary kind. Each needs exactly one branch and no other option, and the remote must be a name, not a URL or path. Multi-branch deletes, `:branch` refspecs, a forced remote-tracking delete and `--delete` with other push options stay denied.

A merged-delete must stand alone. A command line of more than one segment containing one is denied ("Execute branch deletions separately"), and so is one with `-C`, `--git-dir`, `--work-tree`, a `GIT_DIR` or `GIT_WORK_TREE` assignment, a wrapper (`sudo`, `env`, `nice`, `xargs`) or a command substitution ("Branch deletion must run plainly in the session repository").

The Python hook then allows it only when the branch is merged, whatever the run state, and also when no engine can load. The branch must exist, must not be the default branch or the checked-out branch, and must be merged into the default branch by one of: the tip is an ancestor of it; the tip's tree appears among the default branch's first-parent commits (a squash merge); or the tip is an ancestor of a local or remote-tracking branch that meets the tree rule. Evidence is computed afresh at each delete. A remote delete also needs the remote's push URL to equal its fetch URL and `git ls-remote` (3 second timeout, no prompt) to return the tracking sha. Default refs are matched by exact full refname, and the deleted branch name must match its ref exactly, case included (on a case-insensitive filesystem the default and checked-out checks compare case-folded); a branch with a case-variant twin in the same namespace is never deleted. Otherwise the deny reads "Branch B is not merged into DEFAULT (no ancestor, tree or covering-branch evidence)". While autonomy is active a merged-delete is allowed on the same evidence, as cleanup (see Autonomy boundaries). `gate` refuses these commands and every other boundary command: they run only through the guarded hook.

## Hook failures and the session directory

- **Missing cwd.** A PreToolUse payload whose session directory no longer exists denies the delegated classes (release, release-multi, boundary) with "Session directory no longer exists: cd to an existing directory, then retry". Other classes behave as before. The mod spawns the Python hook from the plugin root and passes the session directory in the payload.
- **State busy.** Hook state reads wait up to 2 seconds for the state lock instead of blocking. When the lock is still held, PreToolUse denies the delegated classes with "Orchestra state is busy; retry"; every other class keeps the raw-state fallback. On Stop with autonomy armed in the raw state, the hook waits up to 8 seconds for the lock; if it stays held, the stop is allowed, one brief with reason `state busy` is appended to `progress.md`, and `state.json` is not changed, so the next Stop resumes the run. An unarmed Stop returns at once and writes nothing.
- **No Python 3.11.** `run-hook.sh` probes each candidate interpreter, so a broken shim (such as a pyenv shim with no installed version) is skipped. When none is Python 3.11 or later, PreToolUse fails closed (exit 2) and every other event only shows a warning (`systemMessage`, exit 0).
- **Guard errors name their class.** The mod's fail-closed reason reads "Orchestra guard error (spawn: CODE | exit N | timeout | bad output); failing closed"; an exit-2 deny shows its own reason.

## Autonomy boundaries

While `autonomy arm` is active, the hook and the engine enforce the approval boundaries: no release, permit or deploy; no push except the pull request push; no pull request merge except through the merge guard (below); no deletion except cleanup; no local merge on the default branch; no `gh workflow run`; no `gh pr edit --base` and no other release-class `gh` command; no scheduler tool (`CronCreate`, `ScheduleWakeup`, `RemoteTrigger`); no edit of `.claude/settings.json` or `.claude/settings.local.json` (`protected.autonomy_files`). A denied boundary tells the coordinator to park the card with `park TASK --reason ...` and continue with other cards. Release permits stay unavailable until the user disarms, with one exception: when the ledger holds `- Release: pre-authorized <remote> <target>` equal to `policy.release`, a release-class command alone for that exact remote and target skips the autonomy deny and still needs a current permit, and the engine issues `permit` and `release` for that pair only. A release inside a multi-command line, every other push, merge, deletion and permit stay denied. Stop never arms autonomy by itself.

The pull request push is allowed only in the exact shape `git push <remote> <refspec>`, with `-u` or `--set-upstream` allowed anywhere in the command. The remote is a configured remote by name, not a URL, with neither `remote.<name>.push` nor `remote.<name>.pushurl` configured. No env prefix, wrapper, `-c`, `-C` or other push option is allowed. The refspec names one branch: `<branch>`, `HEAD` or `@` (the current branch), or `<src>:<branch>` or `<src>:refs/heads/<branch>`. The source must be a local branch, or `HEAD`/`@` on a branch. The destination must be a branch, never a tag or a `heads/`, `tags/`, `remotes/` or other `refs/` form, and it must differ, compared case-insensitively, from the remote's default branch, `main` and `master`. The default branch is the one the remote reported when autonomy was armed: `autonomy arm` runs `git remote set-head <remote> --auto` for every remote, stores each answer in the run state (`remote_defaults`) and reports it in its preconditions. A recorded `refs/remotes/<remote>/HEAD` alone is never trusted, since the remote may have changed its default; a remote that did not answer gets no pull request push until autonomy is armed again. The remotes are asked before the armed state is written, so an `arm` interrupted during that step leaves autonomy off. `arm` also records where each remote pushes to (`remote_push_urls`, from `git remote get-url --push --all`, which applies `pushurl`, `insteadOf` and `pushInsteadOf`); a push is refused when that answer differs at push time, so a changed URL or rewrite cannot redirect an approved push whichever setting caused it, a remote with more than one push URL gets no pull request push, and a state armed without the record allows no push. The destination is never the configured release target (that needs the pre-authorized permit), and a state whose ledger does not allow pull request pushes (`pull_requests` not true) allows no push. A bare `git push`, a detached `HEAD`, a force push or a push from another repository stays denied. `gh pr create` is not a release action, and the run may also review and approve pull requests with `gh pr review` and the allow-listed `gh api` writes. Merging follows the approval flow below.

Merged cleanup: under autonomy the coordinator may clean up merged work. `git branch -d|-D <b>` and `git push <remote> --delete <b>` are allowed only when the branch is provably merged into the default branch (the merged-delete check above: ancestor, squash tree match or covering branch), or when it is a run branch, one absent from the local and remote branch lists recorded at arm and named by no recorded pull request, whose tip a remote branch other than its own counterpart contains (`hooks.py` `_run_branch`, `_held_elsewhere`). `git worktree remove <path>` without `--force` is allowed only for a linked worktree of this repository whose checked-out branch passes the same check, and never for the session's own directory or the main worktree; Git itself refuses a dirty worktree. `git worktree prune` is allowed. Each must be a plain single command: no chaining, quoting, wrappers or `-C` (`hooks.py` `_autonomy_cleanup`). `rm` and `find -delete` are allowed as a plain command whose every operand lies inside a linked worktree and outside `.git`; an operand with a leading `~` is refused and a glob is judged by the directory before its first glob character (`_rm_in_worktrees`). Every other deletion stays denied.

## Guard modes

`policy.json` `guard_mode` is `normal` (default) or `protect`. `hooks.py` `_guard_mode` reads it on every PreToolUse call: no state file is `normal`; a policy that cannot be read or checked, or any other value, is `protect`. The engine rejects an invalid value at `start` ("Invalid guard mode") and an unknown policy key (`Engine._check_policy_keys`). `release_workflows` (default `release*`, `publish*`, `deploy*`) lists the workflow names that stay releases; `gh workflow run NAME` is allowed outside a locked state only when NAME matches none of them and a file for it exists under `.github/workflows` (`_workflow_is_plain`).

Where autonomy is active or the unattended lock holds, the effective mode is `protect` whatever the policy says (`_decide`, `locked`). "Locked" below means either.

| Call | `normal` | `protect` | Locked | Code |
| --- | --- | --- | --- | --- |
| `git stash` (every form), amend, multi-ref push, push with a deleting refspec | allow with a warning; a push that deletes a tag, the default or a protected branch, or whose default cannot be resolved, is denied | deny | deny | `_decide` (deny branch with `soften`), `_soft_push_refusal` |
| `git add .`, `git commit -a` | allow | deny | deny | `_decide` (`soften == 'allow'`) |
| Release-class command alone | allow | current permit, else ask | autonomy: deny, except the pull request push and the pre-authorized release; unattended: deny | `_decide`, `_pull_request_push`, `_preauthorized` |
| `gh pr merge N` and `gh api` merge calls | merge guard decides when it gates (below) | same | same | `_merge_gate`, `approval.py` `merge_decision` |
| `gh workflow run NAME` | allow for a plain workflow, else release class | same | release class (autonomy: deny) | `_workflow_is_plain` |
| `gh pr edit --base`, `gh api` write outside the allow list, unknown `gh` command | release class | release class | release class | `guards.py` (`prbase`, `apiwrite`, `ghcustom`) |
| `gh pr create`, `gh pr review`, allow-listed `gh api` writes and reads | allow | allow | allow | `guards.py` (`gh_builtin`, `release.gh_api_autonomy_allow`) |
| Git or `gh` configuration change | allow | allow | autonomy: deny; unattended: allow | `_decide` (`decision.boundary == 'config'`) |
| Branch or worktree delete, `rm`, `find -delete` | merged-delete rules | same | autonomy: cleanup rules above; unattended: merged-delete rules | `_merged_delete_check`, `_autonomy_cleanup`, `_rm_in_worktrees` |
| Local merge on the default branch | allow | allow | deny | `_on_default_branch` |
| Edit of `.claude/settings.json` or `settings.local.json` | allow | allow | deny | `_autonomy_file` |
| `CronCreate`, `ScheduleWakeup`, `RemoteTrigger` | allow | allow | deny | `_SCHEDULERS` in `_decide` |
| Scheduler or `SendMessage` input holding only the approval word | deny | deny | deny | `_carries_approval_text` |
| `autonomy disarm`, `start --new-run` from a tool call | allow | allow | deny; `autonomy arm` is denied only while autonomy is active | `_switches_autonomy`, `_starts_new_run` |
| `Agent`, `Task` outside `orchestra:*`; subagent outside `orchestra:*`; reviewer test run | warn | deny | deny | `_decide` (Agent guard, Subagent guard, Reviewer test block) |
| Release, merge or boundary call while the state lock is busy | allow | deny | deny | `_decide` (`BUSY`) |

## The unattended lock

A run that stopped and kept its report, with no owner receipt for its `run_id`, is unattended (`approval.py` `raw_unattended`; the hook reads `state.json` directly, and a file it cannot read counts as unattended, `_raw_unattended`). The effective mode is `protect`, release-class commands, a local merge on the default branch, `autonomy disarm` and `start --new-run` from a tool call, scheduler tools and settings edits are denied, and the deny reason names the way out: type `approved` in the owner's session, or run `orchestra.py autonomy disarm` in a terminal. `orchestra.py start --new-run` itself refuses while the kept report has no receipt (`orchestra.py` `archive_inactive`: "New run refused"), so a run cannot clear its own lock with `interrupt` then `start --new-run`. The lock clears when the receipt for the run is recorded or `autonomy disarm` removes the kept report. `autonomy arm` moves an existing receipt to `approval_history`, so a receipt never survives a re-arm (`Engine.arm_autonomy`).

## Approval and the merge guard

`UserPromptSubmit` runs `prompt_approval.py` `handle_prompt` through `hooks.py` `_prompt_submit`. The prompt must be the word `approved` alone (`approval.py` `APPROVAL_PROMPT`: case, spacing and trailing `.` or `!` ignored); any other prompt gets `{}`. It calls `Engine.stop_stale_autonomy` first, which stops a loop whose deadline passed or that is bound to another session and idle past `worker_stale_seconds`. It then records nothing, and says why, when the state is busy, autonomy is still active, the same call stopped the run from the session bound to it, or the run never stopped; and when `gh pr list --state all --limit 1000` (6 second timeout) fails. Otherwise `Engine.record_owner_approval` writes the receipt; it is the only writer and no CLI command reaches it. Each pull request the run recorded is placed in merge order when it is open, its live head equals the recorded `head_sha` and its current head has a clean review; the stack order starts at pull requests based on the default branch and adds each one based on the head of one already placed. The rest are listed as not approved with the reason (`_sort`). The receipt stores a hash of the prompt, never its text. The reply prints one `gh pr merge N --merge --delete-branch --match-head-commit SHA` per pull request in order, and one sentence: if a later pull request still shows a run branch as its base after its parent merged, run `gh pr edit N --base DEFAULT` first, then the printed command.

`approval.py` `merge_decision` gates `gh pr merge` and `gh api .../merge` once the state holds a recorded run pull request or the run is active or unattended; otherwise it returns nothing and makes no `gh` call. Its answer is final in every mode. It denies a command that is not a plain `gh pr merge` of one pull request number (no chaining, env prefix, `-R`, branch name, or `gh api`), a flag other than `--merge`, `-m`, `--delete-branch`, `-d` and `--match-head-commit`, and a failed or unreadable state or `gh` answer when the pull request is a run pull request or the run is locked. A run pull request based on a run branch is allowed while its parent is open and denied with the `gh pr edit` retarget once the parent has merged. A run pull request based on the default branch is allowed only when autonomy is off, the receipt names this `run_id` and the number, the live head equals the receipt, the command pins that head with `--match-head-commit`, and every lower-order pull request is merged. A pull request the run did not open and whose base is the default branch is denied while the run is active or unattended. The guard writes no state.

## Not contained, and the known gap

Not contained: `UserPromptSubmit` does not prove a human typed the prompt, because the payload does not mark a scheduled, subagent or other-session prompt. The whole-prompt match, the scheduler and `SendMessage` deny, the scheduler deny while locked and the stale stop narrow the window. A prompt scheduled before the stop that fires after it, a message from another owner session, shell schedulers (`crontab`, `at`, `claude -p`), a hostile agent and any tool that merges outside the shell are not contained.

Known gap: a command run from a directory outside the repository and its worktrees (`git -C <run repo> push`) finds no run, so it gets neither the autonomy plane nor the unattended lock. A server-side ruleset on the host (protect the default branch and tags, require pull requests, block deletion and force pushes) is the recommended backstop, and the only one that does not depend on the agent.

## Mods on Claude Code

The plugin registers a function-hook module (`hooks/mods.json`, loaded beside `hooks/claude.json`). It needs a Claude Code build that enables function hooks (`CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`) and exposes the `$` APIs the module uses; tested on Claude Code 2.1.289 (CLI) and 2.1.286 (embedded in Desktop, with that variable set). There is no version floor. The module has no explicit API check. If a needed API is missing, session start fails, the guard stays not ready and guarded calls fall back to the Python hooks; if the module fails to load, the Python hooks guard every call. Both are the safe direction.

When active, the module classifies Bash, Edit, Write and MultiEdit calls in process with a TypeScript port of the same rules and writes a heartbeat marker under `${XDG_STATE_HOME:-$HOME/.local/state}/orchestra/mods/`. A fresh marker whose rules digest matches lets the Python PreToolUse hook return at once; a missing, stale or mismatched marker makes Python guard in full. Release, release-multi and boundary calls are always delegated to Python, because only the engine knows the run, permits and autonomy. So are a shell call whose classifier deny carries `soften`, an `autonomy` or `start --new-run` command and an edit of `autonomy.md` or a settings file, because the mod does not read the policy or the autonomy state (`hooks.py` `_soften_call`, `_ledger_call`). A mod `tool.call` hook can deny but cannot ask, so for release and release-multi calls the Python PreToolUse hook never takes the fresh-marker shortcut: when the decision is to ask, the mod passes the call on and the native hook raises the prompt. The module also adds `/orchestra-board`, `/orchestra-autonomy on|off|status`, verdict and stop toasts and an autonomy status band, and appends the run's standing orders to briefs for `orchestra:` agents. These are display and convenience only. Without mods everything above still works through the Python hooks and the CLI.

## Release hooks

Release hooks check existing permits; a tool request cannot create one. Structured release execution independently checks configured authority, exact command, current final reviews and required gates. Known Git pushes need exactly four argv elements: the engine's resolved Git executable, push, the configured remote and one refspec. The source must resolve to the reviewed full HEAD. Wrappers and global/push options are rejected because they can change repository or destination context. Default policy names no remote, deployment, database operation or release command. Required missing scanners block; optional missing scanners report unavailable.

Workers retain documentation/browser tools and relevant state reads. Native profiles disable nested agent tools; prompts prohibit coordinator writes. Caller-supplied actor names and environment role markers are advisory consistency inputs. They do not authenticate a worker, and arbitrary interpreter writes are outside the shell classifier. Use host sandbox, remote branch protections and tool policies for stronger isolation.

Opening a session never installs old charter healers, stale-state rewrites, fixed product ports, relay forwarding, automatic rollback or source deployment recipes. ActionNotch and Orca integrations remain separate.

Claude Code does not automatically trust bundled hooks. Review and trust the current definition in the host interface; updates can need another review. Installer code never edits trust or uses a trust bypass.

## Windows

The hooks and the CLI run on Windows through Git for Windows' `sh`. `run-hook.sh` accepts a backslash script path, tries `python3.14` to `python3`, `python` and `py -3.x`, and passes `-X utf8`. `orchestra_core/portable.py` holds the platform differences: `msvcrt` byte locks (exclusive only, so a shared request waits like an exclusive one), `CREATE_NEW_PROCESS_GROUP` and `taskkill /F /T` for gates and the push check, no numeric user id (the fallback state root is named for the user), and `%LOCALAPPDATA%` as the state base when `XDG_STATE_HOME` is not absolute. Path checks ignore case. The guard classifies POSIX shell commands; the PowerShell tool is matched and its command is read the same way, so classified commands are caught but PowerShell-only commands are not. A gate runs in a job object (`portable.track`), which lets the engine see and stop what the gate left running. The TypeScript module returns before it writes a marker when the plugin root is a Windows path, so the Python hooks guard every call there; if it ever runs, it starts the launcher with `sh` and forward slashes.
