# Orchestra 3.6.0

A full-read upstream audit of mattpocock/skills and pstack-claude, applied across every skill and agent, plus a stricter e2e gate and model families in the agent files. The purpose is unchanged: run every independent ask in parallel, at full quality and the lowest cost.

## Added
- **A retro before every push.** After a clean review, the main session reads what the run recorded (findings, repair rounds, failed units, gate failures, owner corrections) and writes at most 3 candidates, each with its cheapest home. `orchestra:orchestra` finish.md also gains "Calls waiting on the owner" and "Re-pitch on request".
- **The e2e filter check.** `lean.py gate e2e` exits 3 when the command is `e2e run` scoped only by `--changed-since` and the e2e config (`e2e.config.ts`, `.js` or `.mjs`) has no `filters` text. The check is a plain-text search, so a comment with the word passes, and a repo with no config is not checked.
- **A `skipped-test` scan finding.** The pre-PR scan reports skips that were already in a touched test file, with a count, apart from skips the diff added.
- **New references.** `build/references/boundaries.md`, `build/references/docs.md`, `ship/references/review-bots.md`; new Refactor and Docs modes in `orchestra:build`.
- **The full-read rule.** An upstream audit reads every skill in full on both sides. It is for improving Orchestra's own skills.

## Changed
- **Workflow is the main tool.** Reviewers and repairs are `agent()` calls too; a dependent unit starts only after a script check of its predecessor's commit.
- **Model families.** Agent files use `opus`, `sonnet`, `haiku` and `fable`; a full id pins one model. The guard keys on the agent type, so the one-at-a-time rule for `orchestra:critic-fable` is unchanged.
- **Limits.** Reference files may hold 100 lines (was 60). Skills stay at 70 lines and the coordinator at 200. The layout test now checks strict frontmatter, description length and repeated rule sentences.
- **Scoping.** `--shard` and `--last-failed` no longer count as a scoped e2e run.
- **The scan** reads CONTRIBUTING.md and CODING_STANDARDS.md as rules files.
- **Skills and agents** carry the audit fixes: shared-checkout git rules for builders, a `check:` field per ask, structural blockers in review, triage and bot-comment rules in ship, a performance order in diagnose, the phase-boundary order and a Pause section in large-work. The list by area is in `CHANGELOG.md`.

## Upgrade
Reinstall Orchestra from the marketplace and restart the client. If the project's e2e config has no `filters` key, add one before using `--changed-since` under the gate; the one-line setup is in `skills/verify/references/e2e.md` (`npx e2e guide setup` has the details).
