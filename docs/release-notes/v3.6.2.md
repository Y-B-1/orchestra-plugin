# Orchestra 3.6.2

Three local checks that catch a wrong or missing agentic e2e setup in any repository Orchestra works in, and the rule for hand-started CI. The checks read local files only: they make no model call and install nothing.

## Added
- **`lean.py e2e-doctor [--config PATH]`.** Prints one `ok` or `gap` line per check and exits 0, 1 (a gap) or 2 (bad usage). It checks that an e2e config exists, that its text holds `filters`, that `package.json` lists `e2e` and `@e2e-dev/decision`, that each key name the config names or its provider reads is set in the environment or in a `.env*.local` file beside the config, and that `.agents/skills/e2e/SKILL.md` exists. It prints key names, never values. With no config it prints the setup command. It reads text, so a name in a comment counts.
- **The left-out note.** After a `--changed-since`-only `e2e run` through the gate, a report in which 2 or more tests ran and none was left out gives a note on stderr and `"left_out": 0` on the recorded run. The gate reads `report.json` from `--output`, else from a literal `output` in the config text, else `.e2e`, and only when the file was written after the run started.

## Changed
- **No e2e skip where a config exists.** `gate skip e2e` exits 3 in a repository with an `e2e.config.*` file. `ORCHESTRA_E2E_SKIP=1` is the owner's switch.
- **CI.** Where CI starts only by hand, `orchestra:ship` starts it once on the release head before the tag.

## Fixed
- The search for the e2e config no longer climbs above the repository root (Windows), and stays in the current folder outside a repository.

## Limits
- The left-out note warns and never fails a run.
- The plugin does not install the e2e runner or write its config; a gap that needs a package or a key is the owner's step.

## Upgrade
Reinstall Orchestra from the marketplace and restart the client. In a repository with an e2e config, run `lean.py e2e-doctor` once.
