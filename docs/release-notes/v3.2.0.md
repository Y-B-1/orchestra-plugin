Orchestra 3.2.0 brings back every capability 3.0 dropped from 2.15, and runs faster than 3.0.

## What changed
- **Eleven agents, each with its model and effort pinned.** Back from 2.15.3: `builder-mechanical`, `builder-cleanup` and `operator` on Haiku 5.5, and `reviewer-light`, `reviewer-standards` and `investigator-research` on Sonnet 5.5. The main skill routes each unit by kind and picks the reviewer by diff size and risk.
- **Role skills and shared situation skills.** Six role skills (`build`, `review`, `plan`, `critique`, `investigate`, `operate`) and five shared skills (`diagnose`, `decide`, `test-quality`, `frontend-proof`, `large-work`) hold the 2.15 lessons, updated with the newest mattpocock/skills and pstack ideas. Each loads only when its situation applies, so a routine unit loads none.
- **Pre-PR review loop.** One review after all units land. Each repair is re-reviewed on the files it touched only, until clean, at most 3 rounds, then one Opus repair.
- **`lean.py check`.** A pre-PR diff scan for oversized files, weakened tests, self-mocks, debug leftovers, rule-file and security-relevant changes, and secrets. It never blocks; the reviewer judges each item. See `docs/check.md`.
- **`frontend-proof`: a submit never fails silently.** No disabled button and no early return for empty, invalid or loading fields.

## Benchmark
On five long multi-request prompts, 3.2.0 took **9.5 minutes per task against 11.8 for 3.0.0 and 12.4 for plain Claude Code**, passed 98.8% of hidden tests, and left the least repair work of the three. It costs about 12% more per task than 3.0.0. Details and limits: `docs/BENCHMARK.md`.

## Upgrade
Reinstall from the marketplace and restart the client. No state changes: the ask ledger and `/orchestra:goal` work as in 3.0.0.

## Checks
`scripts/check.sh` (unit tests on Python 3.11 and 3.13, strict plugin and marketplace validation) and `python3 scripts/live-check.py` (three real headless sessions) both pass.
