Orchestra 2.15.3 closes the friction and review notes left from 2.15.2 and 2.15.1.

## What changed
- **Gated merges name the repository:** a merge the guard gates must carry `-R OWNER/REPO`, the repository recorded for the pull request. The printed merge commands include it, so copy them as printed.
- **Resume and repair:** a resumed card's outside-files check skips commits other cards made while it was reported (F112). Two repairs collide only on their own files, so repairs with disjoint files run side by side (F114).
- **Pull requests:** a pull request counts as reviewed only from a clean final review or one that covers every card it carries (N4).
- **Clearer results:** a CLI result carries a `track` line when the track changed since the last result, so the next step shows right after `add`, `accept` or `wave`. `own add` on a reported card keeps its report current after the card's commit was merged into this checkout, and a stale-report refusal names `resume ID` (F117). A sibling commit merged in from its own branch stays that sibling's work after this card takes over one of its files (F121). `--size` choices come from the engine's size list. A newline before a parenthesis in an acceptance line is no trailing-note gap.
- **Board:** the board view has `overlaps`; the Track lane draws "Shares files: a and c" (F39). A pending board note the board has moved past prints the current board line (F118).
- **Hooks:** a read-only investigator's report stays acceptable after later edits (F116). The Stop hook stays quiet while a gate log has no receipt yet (F115). The approval prompt hook shares one deadline across its lock wait and `gh` calls, under the 10 s hook timeout (N2).
- **Merge guard:** under an active run `gh repo set-default` is denied (N1). A lower pull request closed without merging makes the guard say "type approved again" (N3). A gated merge with no method flag is denied (N5), and the deny says "add --merge" (F119). The engine runs `gh` through the approval module's runner with a 6 s timeout (N8).
- **Test-suite classifier:** it reads `coverage run`, option clusters such as `-Bm` and script arguments. An option's value (`--include "*.py"`) is not read as a script.
- **Merge guard, graphql:** `gh api graphql` with `--input FILE`, `--input -` or `-F query=@FILE`, before or after the endpoint, is merge-gated, so a merge mutation read from a file cannot skip the receipt's order and head checks. The gate also reads shell words, so a continued line, a multi-line query, a `bash -c` or `eval` payload, a `/graphql` or URL endpoint and any graphql mutation are checked; a `gh repo set-default` beside a merge no longer shields it, and an attached flag (`gh pr -Ro/r merge 3`) is seen. A must-deny table (110 commands after the receipt, 9 while armed: every merge spelling found so far plus deliberate fail-closed over-denies) now guards every later change to the gate. A run records pull requests of one repository.
- **Merge gate speed:** the gate's scans are linear (an 80 KB padded command took the gate 32 s, now under 0.1 s). A shell command over 128 KB is denied at the hook entry in every mode, before any parse, because a 700 KB command took the real hook 38 s, past its 30 s timeout; write such content to a file first. `gh pr '' merge` is gated, and a printed merge for a repository like `acme/api-graphql` runs after the receipt.
- **Engine refusals:** a malformed `SELF_REVIEW` line names the bad field (F124); `accept` warns about uncommitted card files (F126); `add` refuses a review card whose brief `Lens:` differs from its variant (F122). Repairs whose chains share a file or directory are each flagged when they edit it (F114); a side branch cannot pass off an edit to a sibling's file (F121).
- **Live checks:** new `scripts/live-gh-wizard.sh` and `docs/live-gh.md` for the owner's one-time check of the merge guard against real `gh` (L2). New live scenario `l3` (23 scenarios): background output and a subagent answer that say "approved" reach no approval; 7/7 live pass.
- **Docs:** mods run by default from Claude Code 2.1.287; the README states the live-check evidence (N9); `gate.md` runs the full suite only on the owner's explicit request.
- **Tests:** `report` inside `do` (F89) and the `binds` edge case are pinned. The merged-delete hook tests use a temporary state home, so test runs leave no policy-only folders in the state directory.

## Known gaps
- `t3` still skips headless: the board mod's task calls do not appear under `claude -p`, so native task renumbering is proven by mod unit tests only. The skip note says whether the mod loaded.
- L2 needs the owner to run `scripts/live-gh-wizard.sh` once.
- Windows and the GitHub branch ruleset are untested.
- The sibling check tells sibling work apart only by the files a commit touches (see the changelog).
- Repairs that each touch one file run one after another (F125).

## Native task tools
On Opus, Sonnet and Haiku 5.5, Claude Code withholds `TaskCreate`, `TaskUpdate` and `TaskList` unless the session starts with `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`. Without it the board's task mirror stays off.

## Install

```sh
claude plugin marketplace add Y-B-1/orchestra-plugin
claude plugin install orchestra@orchestra-distribution
```

Already installed: `claude plugin marketplace update orchestra-distribution`, then `claude plugin update orchestra@orchestra-distribution`. To receive releases on their own, open `/plugin`, go to Marketplaces, select `orchestra-distribution` and choose Enable auto-update.
