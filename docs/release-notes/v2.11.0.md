Orchestra 2.11.0 stops blocking routine git work in normal sessions and lets an autonomous run carry its pull requests all the way to your approval.

## What changed
- **Normal mode is soft:** the policy key `guard_mode` defaults to `normal`. Stash, wholesale `git add`, `commit -a`, amend and multi-ref pushes warn or pass, and release actions run without a question. Set `guard_mode` to `protect` for the strict verdicts. An autonomous run is always strict.
- **Pull requests from an autonomous run:** the run pushes its own branches, opens, reviews and stacks pull requests, and never merges to the default branch, deletes tags or releases.
- **You type "approved":** after the run stops, `approved` in your session records a receipt. The reply lists one merge command per pull request, in order, pinned to the recorded head, and the guard lets only those merge. Until you approve (or run `autonomy disarm`), the stopped run stays locked and `start --new-run` is refused.
- **Guard fixes found in review:** a `gh` flag such as `-R owner/repo`, a backslash line continuation, or `<<` inside shell arithmetic no longer hides a merge, release or force push from the guard (these gaps date from 2.10.0). The stopped-run lock also reads quoted and `find -exec` forms of a release or repository delete. In normal mode a softened item no longer relaxes the rest of its command, and a stopped run cannot delete releases or the repository before you approve.
- **Checks run locally:** `scripts/check.sh` runs every check; CI starts only by hand.
- **Guard and engine:** the matcher now covers `CronCreate`, `ScheduleWakeup`, `RemoteTrigger` and `SendMessage`; a call to one that carries only `approved` is denied. New policy keys `guard_mode`, `release_workflows` and `max_worktrees`; unknown policy keys are refused; a pre-2.11 ledger must be re-filled before `arm`.
- **Known gaps:** a command run from outside the repository is not guarded, and a script written then run is not scanned. A server-side branch ruleset is the backstop. Live checks of the prompt hook and the merge guard with real `gh` are still to do (docs/BUILD-LEDGER.md).
- **File budget (off by default):** set `file_budget_bytes` in the policy and `prepr` lists the changed files that grew past it. The standards reviewer gets that list under `## Over file budget`. `file_budget_waivers` maps a glob to a reason.
- **Parallel work:** at most three worktrees at once. Read-only side workers run beside inline work at any size. A medium run escalates once two disjoint units each reach about 600 lines. Near the context ceiling, the remaining units go to builders. `max_workers` is the owner's device and usage limit.
- **Worker results:** a short report is dispatched once more, then recorded as an open gap. A dead worker gets at most two re-dispatches. The first of three or more similar tickets runs alone.
- **Failing gate:** after a `gate-failing` stop, the brief names the gate's last log path.
- **Skills:** new rules for briefs, triage, handoff, design, build, review and critic, from Anthropic's code review posts, pstack and mattpocock/skills. Credits are in docs/SKILL-SOURCES.md.
- **Still open, by design:** the items listed in the 2.9.0 notes. The parallel-work limits are rules in the skills; the engine does not enforce them.

## Install

```sh
claude plugin marketplace add Y-B-1/orchestra-plugin
claude plugin install orchestra@orchestra-distribution
```

Already installed: `claude plugin marketplace update orchestra-distribution`, then `claude plugin update orchestra@orchestra-distribution`. To receive releases on their own, open `/plugin`, go to Marketplaces, select `orchestra-distribution` and choose Enable auto-update.
