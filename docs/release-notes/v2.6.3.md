Orchestra 2.6.3 rolls up 2.6.0 to 2.6.3: a quieter autonomy loop, release actions that ask instead of block, autonomy that opens pull requests and never merges, and fixes from a full audit. Everything was validated live in real Claude Code sessions, including an unattended run from the first message to `complete`.

## Autonomy
- **Quiet loop:** the Stop hook continues a turn only when the coordinator can act now: a ready card, a reported card to review, an open final finding, a held chain owed its final review, or the final phase once every card is accepted.
  - **Waiting on workers:** the turn ends while background workers run, and the session wakes when one finishes.
  - **No repeats:** the same prompt is never sent twice.
  - **Stall:** a turn that changes nothing, with no worker running, stops the run as `stalled` and writes its brief.
- **Pull requests, never merges:** autonomy pushes one feature branch and opens the pull request with `gh pr create`. The push must be exactly `git push [-u] <remote> <branch>`. It is checked against the default branch each remote confirmed at `autonomy arm`, plus `main`, `master` and the release target. Merges and other releases stay blocked; you merge after the run.
- **Arming handles the remotes:** `autonomy arm` asks every remote for its current default branch, so you no longer run `git remote set-head` yourself. It checks the ledger first and writes the armed state last, so an interrupted or refused arm changes nothing.
- **Merged cleanup:** autonomy may delete branches and remove worktrees that are provably merged, and prune worktree records. `rm` and force deletes stay blocked.
- **Pull requests in the brief:** `orchestra.py pr URL` records a pull request the run opened. The run brief lists it under Needs you, along with any cards left unfinished.
- **Relaunch removed:** `orchestra.py relaunch`, `autonomy arm --relaunch` and `autonomy settle` are gone. A 2.5 relaunch state loads but does not re-arm.

## Guards
- **Ask instead of block:** during an interactive run, a release action (`git push`, `gh pr merge`, `gh release create`, publish, deploy) runs with a current permit and otherwise shows Claude Code's approval prompt.
- **More releases recognized:** `gh api` merges, `gh api graphql` mutations or request bodies read from a file, and `cargo publish` are release actions.
- **Aliases and push mappings:** a run cannot set a Git alias or a push mapping (`git -c alias.*=`, `--config-env`, `git config alias.*`, `--rename-section`, `remote.<name>.push`, `remote.<name>.pushurl`, `url.<base>.insteadOf`, `url.<base>.pushInsteadOf`, `include.path`, `remote.<name>.url`, `git config --edit`, and `git remote add`, `set-url`, `rename` and `remove`), which would let a push or merge run under another name or go elsewhere. Reading them still works.
- **Clear denials:** deny reasons start with "Orchestra guard:", so the model reads them as policy, not a tool failure.

## Engine, hooks and packaging
- **Engine hardening:** task JSON cannot set engine-owned fields, and a stale review with findings blocks `accept`. `start --policy` is validated, and CLI errors exit 2 with JSON.
- **Hook startup:** `run-hook.sh` probes each Python, fails closed only on PreToolUse when no Python 3.11+ is found, and warns on other events. The PreToolUse timeout is 30 seconds.
- **Gates and housekeeping:** processes a gate leaves running in the background are stopped when it exits, and a session start deletes the heartbeat markers of sessions that ended more than a day ago.
- **Release archive:** leaves out tests and development files, and scans for more secret forms.
- **CI:** tests run on Python 3.11 and 3.13, plus strict validation and the mod tests, on every pull request. Releases are built and published by a workflow, started by pushing a version tag or by hand from main.
