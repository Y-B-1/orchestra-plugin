Orchestra 2.8.0 adds Windows support, closes the remaining audit items and adds one-time setup advice to the README.

## What changed
- **Windows (new, not yet confirmed on a Windows machine):** the hooks and the CLI are written to run with Git for Windows and Python 3.11 or later. The Windows CI job had not reported when this was released; treat Windows as experimental until it has. The launcher accepts backslash paths, tries `python` and `py -3.x` after `python3`, and starts Python in UTF-8 mode. Run state lives under `%LOCALAPPDATA%\orchestra`. The TypeScript module stays inert on Windows paths. The PowerShell tool is outside the guard.
- **More releases are recognized:** `docker push`, `terraform apply`, `helm upgrade`, `kubectl apply`, `yarn`/`bun`/`poetry`/`uv` publish and more deploy tools.
- **Clearer denials:** the destructive Git denials name the safe alternative, and an over-long command says to use the Write tool.
- **Autonomy:** pushes to `production`, `gh-pages`, `release` and similar branches are refused; the default branch follows what the remote reported at arm; a silent worker is surfaced and then stops the run as `stalled`; a required gate that fails three times in a row stops it as `gate-failing`.
- **Large files:** files over 64 MiB are bound by size, mtime and samples instead of being read whole.
- **README:** a one-time section with global `CLAUDE.md` and project `AGENTS.md` advice and a script that lists what your sessions load.

## Install

```sh
claude plugin marketplace add Y-B-1/orchestra-plugin
claude plugin install orchestra@orchestra-distribution
```

Already installed: `claude plugin marketplace update orchestra-distribution`, then `claude plugin update orchestra@orchestra-distribution`.
