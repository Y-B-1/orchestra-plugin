# Skill sources: capability matrix for Orchestra v2

Card MX (PLAN-v2), revised by MX repair rounds 1 and 2 after the MXR reviews. Input to the S1 to S7 authoring tickets and to the cohesion review (SPEC-v2 8.4). Started from commit `512bfac2159ba9c3e680db5af621f379eef50be5`; repair round 1 started from `2c515f5251c2a688965e33bc991e5c7eaa039728` and round 2 from `ff543117c7716ccf2abf52c5ceaf383e5d5814da`; both are checked against SPEC-v2 and PLAN-v2 at round 6 (`3e0889d1faf998c0b666cd1750e0e08f0b695546`). Built from the pinned upstream texts of RESEARCH-v2 I2 and the v1 Orchestra method files.

Skill curation is a synthesis. Each row takes a base text, merges in the stronger elements of the other sources, fills gaps with Orchestra text, and names the files that carry the result. Superpowers is the base wherever it has a candidate. Nothing upstream is copied: each skill file is new text in Orchestra vocabulary, written from its rows.

## Legend

- Upstream paths are relative to the pinned repository root (`repo@sha12:path`). "same dir:" lists files under the directory of the path before it. Line ranges are written outside the backticks.
- `v1 X.md` means `plugins/orchestra/skills/orchestra/references/X.md` at `512bfac`, the existing Orchestra method text. It is part of the synthesis, not discarded.
- Destination cells list paths relative to `plugins/orchestra/skills/`, each in backticks. Every destination of a row whose License cell names an upstream or idea-level source carries a `Source:` header (SPEC 8.2, 8.3). The one exception is `orchestra/references/cli.md`: Orchestra text only, with no `Source:` header and no `Stub:` line, skipped by the provenance tests (SPEC 8.4).
- "none" in a source column means the source has no candidate text for the row. "fragment, merged" means the source has only a partial text for the row (cited with its line range); the fragment is merged, and the base comes from the source with a full candidate. "fragment, adds nothing" means the partial text is rejected in that row.
- Merged elements are numbered. An additive element brings content the base lacks and does not change the base; it carries the words "adds to the base", and its text names what it adds. An element that overrides or replaces part of the base says which part it replaces and carries a short "Stronger:" reason.
- License per element follows its source in the Sources table: an element from an MIT source is MIT text; an element from an idea-level source is an idea whose text is never copied. A License cell lists only the sources whose text or ideas the row uses; a candidate whose elements are all rejected is cited in its column but not credited.
- Rejected holds only elements that conflict with Orchestra (the 8.2 avoid list, never-pause, personas, telemetry, a host feature subagents lack, the owner-trigger rule for the full suite, no delegation or user interaction inside workers) or add nothing.
- Worker limits used in rejections: workers have no Agent tool, no Skill tool and no user interaction; read-only roles have no Edit or Write.
- `orchestra-worker/SKILL.md` has a 2,048-byte budget (SPEC 8.3). A row that routes to it says in its Synthesis notes which exact part goes there; everything else in that row goes to a role skill or to `orchestra/references/briefs.md`.
